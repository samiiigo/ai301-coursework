# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | Plan-context scope, exclusions and deviations paired with every changed behavior/file in the diff; candidate title and description paired with that diff. | The diff implements the stated plan or explicitly recorded deviations, and the description accurately states what was delivered and omitted. Any material addition, omission, or changed approach is explained in the plan's deviations and reflected in the description; an honestly bounded partial outcome may pass, but silent drift or a contradicted claim does not. | required |
| observable-proof | Candidate test evidence paired with the original repro and the plan's test plan, including boundary cases. | Commands or concrete steps, inputs, and observed before/after outcomes establish the claimed behavior on the changed path. Relevant planned boundaries are exercised or their untested status and limits explicitly disclosed; a real negative or partial result may pass when the claims are narrowed accordingly. An assertion such as "tests pass", a test file without execution evidence, or proof of a different path does not pass. | required |
| repository-checks | Repo-facts check requirements paired with test-evidence command results and description checkboxes. | The repository's applicable checks have actual reported attempts and outcomes, including failures or empty suites with reasons and accurate limitations. A disclosed failing attempt is evidence, not a claimed pass. Required checks silently omitted or only promised for later fail. Do not invent checks the repository never requested; a documented inapplicable check needs no execution. | required |
| focused-diff | Unified diff and commit list paired with issue scope and plan boundaries. | The issue's change is inspectable without unrelated edits, formatting churn, debug leftovers, dead code, or commented-out experiments. Necessary supporting changes and regression tests are allowed. An unrelated cleanup fails even if disclosed; commit count or diff size alone does not decide reviewability. | required |
| stated-standards | Repo-facts template, contribution policy, thread direction and live course requirements paired with candidate title, description, and branch/commits where specified. | Every applicable template section has substantive content or a justified N/A; the issue is identified, explicit maintainer requests are addressed, and required AI-use disclosure and other stated submission requirements are met. Do not impose an unstated AI policy. For a pre-opening Path Review draft, leave CI unchecked: the assignment explicitly defers CI until a PR exists. | required |

## Verdict rule

Return accept only if every required check passes. Any required fail or unclear returns reject; missing evidence is not a pass. Preferred checks, if added, never change the verdict. Grade each check independently: an honest disclosure can satisfy fidelity or qualify test claims, but cannot excuse unrelated edits, unattempted required checks, or an explicit submission policy. Do not require a perfect outcome when the supplied evidence supports an accurately disclosed partial outcome.
